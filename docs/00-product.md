# 产品定义

## 1. 一句话

**Bookloom 是一个本地优先的电子书工作台：把杂乱的书稿整理成结构正确、元数据完整、排版舒服的电子书。**

它不只做格式转换，而是覆盖「导入 → 识别 → 校对 → 元数据 → 封面 → 导出 → 书架管理」的完整流程。

## 2. 要解决的问题

现成工具通常只解决一段：

- 转换器只管 TXT → EPUB，分章错了只能重来；
- 编辑器不管 EPUB / DOCX 的样式和元数据；
- 排版工具要求先把稿子整理干净；
- 在线工具需要上传文件，隐私和断网场景不成立；
- 桌面工具往往只支持 Windows，移动端缺失。

Bookloom 的目标是让个人作者、校对者和轻量出版者在一个应用里完成整条链路，默认全部离线处理。可选 AI 校对是明确的联网例外：用户自行配置服务并主动触发，连接测试只发送固定小样本；书稿分析入口尚在开发，不得把启用配置当成上传整本书的授权。

## 3. 目标用户

| 用户 | 场景 | 关键诉求 |
| --- | --- | --- |
| 网文作者 / 校对者 | 几十万到百万字的 TXT 稿 | 编码识别、分章准确、批量修正、EPUB 导出 |
| 个人出版者 | 自己排版一本小书 | 元数据、封面、目录、EPUB 3 / 2 兼容 |
| 轻量编辑 | 把 DOCX / EPUB 重新整理 | 保留卷章结构、图片、脚注、可继续编辑 |
| 多设备用户 | Linux 桌面 + Windows + Android | 同一套体验、书架可迁移、不依赖云 |

## 4. 产品原则

1. **本地优先**：默认不联网，不上传书稿，不需要账号。
2. **数据可带走**：书架、草稿、封面、原文可打包导出，不锁死在应用里。
3. **先结构后排版**：章节、卷、目录正确，再谈字体和 CSS。
4. **渐进复杂**：默认界面只放常用项，高级排版和元数据折叠起来。
5. **一套核心**：桌面和移动端共享解析、编辑、导出逻辑，不按平台写两套业务。
6. **失败可恢复**：自动保存、撤销/重做、导入失败不破坏原文件。

## 5. 1.0 范围

### 必须有

- TXT 导入：UTF-8 / GBK / GB18030 / Big5 / UTF-16 自动识别 + 手动切换。
- EPUB 导入：spine 顺序、nav / NCX 层级、封面、书名作者、扩展元数据。
- DOCX 导入：Heading 1/2（含中文「标题 1/2」）还原卷章；无样式退化为单章并提示。
- 章节编辑：改标题、合并、拆分、删除、升降级、搜索跳转。
- 校对工具：撤销/重做、批量替换、全书体检、章号重编号。
- 元数据：书名、作者、简介、系列、出版社、标签、出版日期、语言。
- 封面编辑器：竖排 / 色块模板、配色、字号、作者位置、实时预览。
- 导出：EPUB 3、EPUB 2、DOCX、单文件 HTML、TXT、Markdown。
- 书架：多书管理、封面缩略图、最近打开、本地占用、备份 / 恢复。
- 繁简转换：OpenCC 规则，标题和正文一起转换，切换可恢复。
- 自动保存与崩溃恢复。

### 1.0 不做

- 云同步、账号体系、在线书城。
- DRM 解密、盗版内容分发。
- MOBI / AZW3 读写。
- PDF 编辑或 PDF 重排。
- 自动在线改写 / 云翻译；可选、主动触发的 AI 校对扩展按 `development/02-ai-proofreading-and-rule-engine.md` 独立推进，不影响离线核心。
- 插件市场、脚本系统。

## 6. 平台策略

| 平台 | 定位 | 优先级 |
| --- | --- | --- |
| Linux | 桌面主力，AppImage / Flatpak / deb | P0 |
| Windows | 桌面主力，MSIX / 安装包 | P0 |
| Android | 移动端阅读/轻编辑，SAF、分享 | P0 |
| macOS | 后续，同一 Flutter 代码 | P2 |
| iOS | 后续，需 Mac + Xcode + 开发者账号 | P3 |
| Web | 不在此项目内；现有 txt2book 可继续作为轻量 Web 版 | 独立 |

Android 不是“缩小版桌面”：要针对 SAF、分享、软键盘、长按选择、后台切换单独设计交互。

## 7. 成功标准

- 100 万字 TXT 在普通笔记本上 10 秒内完成解析并进入可编辑状态。
- 导出的 EPUB 3 / EPUB 2 通过结构校验，Calibre 打开无警告。
- DOCX 在 Word 中打开无「修复」提示。
- 从导入到导出，全程无网络请求也能完成。
- 清空应用数据前，用户可以用备份文件完整恢复书架。
- 三个平台的核心导出结果一致（同一输入、同一设置）。

## 8. 体验指标

- 冷启动 < 2 秒（已有书架，不含大书恢复）。
- 章节切换 < 100ms；输入无肉眼可见卡顿。
- 自动保存延迟 0.8–1.5 秒，不阻塞输入。
- 1,000 章目录滚动稳定；不一次性构建全部章节正文。
- 移动端常用操作不超过 3 步：导入、改标题、导出。
