## 1. 目标、依据与实际起点

### 1.1 本轮目标

让 Bookloom 从已有的视觉与数据骨架，成为能够独立完成「导入 → 分章 → 编辑校对 → 元数据与封面 → 排版预览 → 导出 → 书架续编与备份」的原生应用。

覆盖现有 txt2book Web 版的主要业务能力，同时改进浏览器版的离线词典、保存可靠性、任务取消、正则执行和文件管理。保留 Flutter + Dart + Riverpod + Drift，支持 Linux、Windows、Android；**不是为 Bookloom 新增 Web 构建，也不是把网页嵌进 WebView**。

本轮是一个包含多个可验收批次的完整计划，不要求所有功能一次上线。先交付可保存、可重开的 TXT → EPUB 3 闭环，再逐批补齐；尚未通过验收的批次保持未完成。

## 3. 核心使用流程与页面组织

### 3.1 导入与首次编辑

1. 书架「导入书稿」与导入页进入同一流程；取消文件选择安静返回，不创建空书。
2. 选一个文件进入单本导入；选多个文件先显示队列，并明确选择「加入书架」或「批量转换」。不把多选无提示地变成只导出不保存。
3. 显示格式、文件名、大小、解析选项与阶段进度。TXT 提供编码、广告过滤、识别规则、转换方向；EPUB / DOCX 不显示无效的编码重识别操作。
4. 解析完成显示章数、字数与必要警告；有低置信度编码时可查看片段并重选。未经确定不自动毁弃已有编辑。
5. 校验并保存成功后进入工作台；失败 / 取消不留下半本书和孤立资源，原文件始终不变。

### 3.2 编辑工作台

建议新增顶层推入路由 `/books/:bookId`，返回书架时保留原来的搜索、排序与滚动位置。使用已有窗口 caption、返回入口和透明 Scaffold；不叠出应用主侧栏与章节侧栏两套常驻导航。

| 可用窗口宽度 | 工作台布局 |
| --- | --- |
| ≥ 1280 | 约 240px 章节目录 + 可伸缩正文 + 约 304px 书籍设置；按实际正文最小宽度校验，不能仅判断设备类型 |
| 960–1279 | 章节目录 + 正文；元数据 / 排版 / 封面按需在弹窗或独立编辑区域打开 |
| < 960 | 正文为主，目录与设置按需切换或弹出；保留返回、保存状态与导出入口，不常驻三栏 |

- 章节目录和正文各自滚动，避免整页滚动把常用操作带走。目录用懒加载列表，正文按当前章 / 块加载。
- 「编辑 / 预览」是同一份书稿的两种视图，不存两份可编辑内容。预览的标题、层级和文本来自同一模型。
- 结构操作在目录或选段操作处出现；校对 / 查找替换按需打开。高级 CSS、字体、规则 JSON 不挤占日常编辑空间。
- 顶部保留书名、必要保存状态、撤销 / 重做与导出；不重复页面大标题、宣传口号和装饰性英文眉标。
- 正文与设置落在不透明 `surface`；只给壳层、浮层等使用已有 GlassSurface。保留当前书架、设置、关于页的视觉成果。

### 3.3 书架与批量任务

- 书架提供紧凑搜索 / 排序、主要导入动作、真实书籍卡片与空状态；删书前确认对象，删除结果不影响其他书。
- 打开其他书前保存当前编辑；保存失败时给出重试 / 取消切换，不静默跳走。
- 批量任务列出等待、处理中、成功、失败、已取消状态；显示成功数、失败原因和重试入口，不用一条总 Toast 代替结果。
- 保存成功只在真实提交后显示；未实现、未写入、未分享均不能反馈为成功。

## 4. 数据与架构：先补当前骨架的缺口

### 4.1 一份当前内容与原文件

每本书只有一份当前可编辑数据。原始文件只读保留，作为重新解析依据；撤销是有预算的会话内命令栈，**不新增业务历史版本、修订列表、并行草稿、确认版或发布版**。

书籍存储仍为 `<app-support>/books/<bookId>/`。原文、封面、缩略图、字体和后续插图放文件系统，SQLite 存引用与结构。相对路径必须限制在该书目录内。

### 4.2 需要补充的模型契约

| 契约 | 当前差距 | 本轮决定 |
| --- | --- | --- |
| `ParseOptions` | 尚无独立模型 | encoding、filterAds、rulePreset / ruleSpec、convertMode；按书保存最后一次成功应用值 |
| `ParseResult` | 只有 Book 等基础模型 | 格式、编码 / 置信度、书名作者建议、章节块、封面建议、带定位的警告与来源映射；先作为导入暂存结果 |
| `Chapter` | 有 parentId / level，无前言语义 | 增加 `frontMatter` 或同等明确字段；保留前言内容，导出不强插「前言」标题；卷章严格限两级 |
| 卷结构 | Web 仅靠平铺 level | 导入时归一化 parentId；移动 / 升降级 / 删除后不得出现环、跨书父节点或悬空章节 |
| `LayoutOptions` | 缺 kai、customCss、字体引用 | 补楷体角色、导出 CSS、embeddedFontAssetId；基础属性校验单位、范围与缺省值 |
| `CoverOptions` | 缺 auto、作者隐藏，block / blocks 命名不同 | 对外 wire 值明确，兼容输入映射；补自动配色、hidden；区分模板参数与当前封面来源 |
| 元数据 | 基础字段已有，序列化和校验未完整 | 日期按 YYYY-MM-DD 的日历日期处理，不能因时区变成前一天；标签去空去重，简介按纯文本处理 |
| 当前封面 | 仅有 coverAssetId | `coverMode` 区分 template / image；调模板参数不自动改 image 模式，切换时保留用户选择的当前图像引用 |
| 每书排版 / 导出 | 只有部分 JSON 模型 | 每书当前选项独立保存；全局默认只影响新书，不反向改写所有旧书 |
| 编辑并发标记 | 尚无 | 仅使用当前内容的递增 revision / saveSeq 拒绝过期结果；它不是历史数据表 |

### 4.3 schema 与实现差异处理

批次 A 先以真实 schema 为准编写迁移，不覆盖重建用户数据库：

- 当前 `Sources.bookId` 没有书籍外键；`Books.coverAssetId`、`Blocks.assetId` 也未实现逻辑文档中的全部关联。补足安全的外键与 Repository 级同书资源校验，处理既有无效引用，不盲目制造循环建表依赖。
- schemaVersion 1 当前只有 onCreate / beforeOpen；增加 onUpgrade 和旧库迁移测试，新字段 / 新表随真实改动升版本。
- 逻辑文档写 UTC 毫秒，而代码使用 Drift DateTimeColumn。先核定实际存储单位与序列化方式；数据库按明确的 Drift 配置处理，备份时间统一 ISO 8601 UTC，不能把旧秒值当毫秒直接读写。
- 当前 `WordCount` 按 rune 计数，但只排除代码列出的有限空白，U+2003 等仍会计入；不能称为已实现完整的非空白 Unicode 计数。批次 A 固定统一规则：沿用 Web `\s` 的空白集合，补全原生遗漏，加入普通空格、全角空格、NBSP、U+2003、BOM 与 emoji 用例；按 Unicode 标量计数，标点计入，章节标题不计入正文。书架、目录、体检、导出摘要共用，升级时重算受影响摘要。旧文档的「英文按单词」不采用；Web UTF-16 length 与原生 emoji 计数的差异明确保留，不假装逐项数值相同。
- 当前 core 模型引入 `flutter/foundation.dart` 作注解，与「纯 Dart 核心」目标有差距；新增解析 / 编辑 / 格式算法不引入 Flutter UI，先解除必要的注解耦合，再用纯 Dart 用例验证。
- 新增 `rules` 等表只在确有多条用户规则集合需求时创建；每书的一份规则与参数可先用归一化 JSON 保存。不要为规划中的扩展预建一批空表。

### 4.4 建议的模块边界

```text
lib/core/
  parsing/       TXT、EPUB、DOCX 与章节识别，返回统一中间结果
  editing/       分章 / 合并 / 层级、命令与撤销、替换、体检
  conversion/    离线繁简转换
  formatting/    共用文档结构、目录、EPUB 3/2、DOCX、HTML、TXT、Markdown
  storage/       书籍 Repository、迁移、资源引用、备份
  platform/      选文件、保存、目录 / URI、分享与任务生命周期适配
lib/features/
  import/        导入与批量任务编排
  library/       书架查询与书籍操作
  editor/        编辑会话、目录、正文、校对、元数据 / 排版 / 封面入口
  preview/       原生阅读预览与封面渲染
  export/        输出选项、进度、结果与设备帮助
```

这是职责分配，不要求机械创建所有空目录或框架。遵循现有项目结构，UI 依赖应用编排，算法不访问控件和数据库；平台差异收敛在接口实现内。

### 4.5 关键应用接口

- 文件服务：选输入、打开字节流、创建导出目标、写入 / 结束 / 取消；Android content URI 不能伪装成普通 File 路径。
- 导入服务：输入暂存路径 / 字节流 + ParseOptions → 可校验导入结果；失败不提前改写书架。
- 书籍 Repository：目录摘要、按章 / 块加载、当前书籍变更事务、摘要增量更新与资源引用校验。
- 编辑会话：当前书、活动章 / 块、dirty、saveSeq、保存错误、命令历史；Riverpod 不持有每次按键复制的全书正文。
- 导出服务：一致的 `ExportSnapshot` + 格式参数 + 目标 → ExportResult；快照仅是任务期只读输入，完成后释放，不持久化成业务版本。
- 后台任务：jobId、输入 revision、阶段、进度、取消；只接受当前任务的响应，旧结果不得覆盖新编辑。

## 5. 导入、识别与原文处理

### 5.1 TXT 基线

顺序固定为：复制原文 → 编码判定 → 换行 / 控制字符归一化 → 可选广告清洗 / 规则 → 段落还原 → 分章 → 简繁转换 → 校验 / 统计 → 提交。

- BOM 优先；非 BOM 先严格 UTF-8，再比较其他候选。展示实际编码、置信度和警告，不把 ASCII 测试结果误当所有中文编码均正确。
- 识别缩进型逐行段落与硬折行，保留合理段落；英文合并时补空格，不能把词粘在一起。
- 保留「第 X 部分 / 部门 / 部队 / 部件」不是卷、最终章 / 完本感言、英文 Section / Page、问叹号标题、标题号与标题粘连等回归语义。
- 目录页必须结合位置、密度与连续标题判定，不能按「目录」两个字无条件删除正文。
- 无标题时按空行退化；纯无结构文本生成单章并说明。超长无标点输入分块处理，不让一个 TextField / 段落持有无限内容。
- 原文缺失时允许继续编辑当前内容，但禁用依赖原文的重新识别，并提供重新选择源文件的操作。文件重新关联需验证格式与身份，不能把别的书原文错绑到当前书。

### 5.2 自定义规则

保留 `RuleSpec` 的 `id? / name / chapter? / volume? / drop[] / inlineJunk[]`；chapter / volume 按整行识别，drop 是整行删除，inlineJunk 剥离粘连水印，**不是另一套批量替换字段**。

- JSON 读入先做结构、长度、正则语法与危险表达式校验，错误定位到字段；保存与应用失败不覆盖当前有效规则。
- JS 与 Dart 的正则标志、大小写、Unicode、零宽匹配和反向引用不能假定完全相同；建立兼容用例，不支持的表达式明确拒绝。
- 规则不自动联网更新，不运行用户脚本；规则导入 / 导出只包含规则配置，不能冒充整书备份。

### 5.3 EPUB / DOCX

- EPUB：校验容器及 OPF，按 spine 读取；目录优先 EPUB 3 nav，其次 NCX，再读正文 h1–h3。处理相对路径、百分号编码与锚点；目录页不能变成正文重复章节。
- 保留封面与基础 / 扩展元数据，并兼容 calibre 系列兜底；遇 DRM 直接报可理解错误，不做解密。
- DOCX：识别标准 / 本地化 Heading 1 / 2 与 outlineLvl；全书只有 H1 时导入为章，避免生成一串空卷；无样式作为单章并提示。
- 本轮核心按 Web 的文字与封面范围交付。章节插图、脚注关联、表格、文本框、页眉页脚、自动编号或复杂 CSS 不能恢复时，导入结果要列出丢失类型，保留原文件供用户判断；不能宣称无损导入。
- 不得对 EPUB / DOCX 套 TXT 的编码重识别；繁简转换仍可以作用于它们解析出的当前文本。

### 5.4 繁简转换与重新解析的改进

- 保留原样、通用繁体转简体、简体转台湾标准繁体；词典随包分发或作为已安装本地资源，首次断网也能使用。加载许可与体积在批次 A 验证，不沿用 Web 首用下载词典方案。
- 导入阶段转换章节标题 / 正文及推断出的书名作者；用户自行填写的元数据不因后来重新识别被猜测值覆盖。
- 已编辑书籍的简繁切换优先转换**当前内容**并作为一次可撤销命令，不从原文件静默重解析抹掉修改。
- 「从原文件重新识别」是单独的破坏性操作：提示会替换哪些当前章节、先准备结果，确认后事务应用；失败保持当前书稿。不是保存一份新的解析版供并行编辑。

## 6. 编辑、校对与输入体验

### 6.1 结构与正文

- 分章和设标题首先以 Block 边界工作；分章后正文不丢失、不重复，当前选择跟随到新位置。
- 首章不能「并入上一章」；合并、删除卷、升降级必须明确其子章归属，不使用外键级联意外清掉未提示的正文。
- 正文编辑按当前章 / 块加载，保存前后保留光标与选区；不能每敲一个字重新解析整本书或重建整章所有控件。
- 输入法组合期间不触发章节切换、全局替换快捷键、自动格式化或结构命令；组合提交后再保存。
- 预览只是当前模型的另一种呈现。长章采取分块 / 懒构建，不复制 Web 的「只渲染前 120k 字」而让余下正文无入口。

### 6.2 撤销与保存分工

- 结构命令、改标题、替换、重编号、转换等以可逆变更进入统一栈，批量动作合并一步；最多 50 步，并按实际增量字节预算裁剪，避免保存 50 份全书。
- 文本输入合并连续编辑；输入控件聚焦时尊重其局部撤销，不让全局 Ctrl+Z 删除章节。离开输入后，已提交文本与结构操作有明确的历史分界。
- 撤销 / 重做也会更新当前内容并触发自动保存；新编辑清除 redo 分支。重开书稿不恢复会话历史，数据库只保存当前内容。
- 自动保存用 800–1200ms 停顿合并写入；书籍摘要与章节 / 块变更在同一事务更新。旧 saveSeq 完成不能把新变更标成已保存。
- 保存失败保留 dirty 与内存内容，给重试和错误原因；不要沿用外观设置的「best effort、吞错」策略保存书稿。
- 切书、返回书架、窗口关闭 / Android 生命周期变化尽力 flush；崩溃最多可能损失尚未提交的防抖窗口，不能宣传每个按键都已持久化。

### 6.3 体检与替换

- 全书体检覆盖八类问题；按卷识别章号连续性，序章 / 番外 / 完本感言等不强制参与编号。
- Web 初始异常阈值为短章 <120、长章 >30,000 非空白字符。先复用并说明是启发式提示；本轮统一使用原生 WordCount，边界差异有测试。
- 问题输出带 chapterId / blockId 与建议，点击定位；诊断只是建议，不自动删广告或重编号。
- 替换先预览总数和有限条前后文；执行前检查书稿 revision，内容已变化则重做预览，避免显示数量和实际替换错位。
- 普通查找的 `$1` / `$&` 按字面量处理；正则模式建立与 Web 的 `$1`、`$&`、`$$` 等替换语义兼容测试，不直接套 Dart 字符串替换后声称等价。未支持的替换语法明确提示。
- 保留查找 200 字、替换 500 字、200,000 命中的初始边界；零宽匹配保证前进，拒绝明显灾难回溯表达式。原生可在经过测试后集中调整上限。
- 正则执行放可终止 isolate，UI 侧超时可真正终止自己启动的任务；在单个正则返回之后检查时钟不足以阻止卡死。预览 / 执行超时不提交部分变更。

## 7. 元数据、封面、排版与字体

### 7.1 表单语义

书名作者为常用项；简介、系列、出版社、标签、日期、语言放扩展区。显示字段真实用途，清空可选值代表清空，不用「保持 / 替换」模式；新建和已有书籍都只编辑当前数据。

解析猜测只作初始建议；书籍重命名同时更新元数据、书架与后续导出，不能只改列表显示名。文本与日期校验失败就近提示，输入不因失败丢失。

### 7.2 封面

- 竖排与色块模板沿用 Web 思路，auto 及原木 / 墨夜 / 深海 / 酒红 / 松林五套配色，标题倍率初始 0.8–1.3，作者位置上 / 下 / 隐藏。
- Flutter 以同一套 1200×1800 逻辑坐标绘制预览、缩略图与导出 JPEG；不允许预览一套、导出另一套。
- 文件封面先验证 MIME / 解码 / 像素尺寸，再裁切；选图取消不替换当前封面。去除不必要的图片附带信息，失败保留旧图。
- 模板与上传图是明确的两种当前封面来源。与 Web 不同，调整模板参数不会静默覆盖上传图；切换到模板时再应用。保留一份当前数据即可，不引入封面历史版本。
- 预览字体不存在、书名很长、中英文混排和作者隐藏都有降级，不裁掉核心文字；显示结果与导出一致。

### 7.3 排版与 CSS

- 初始保留行高 1.75、首行缩进两字、段间距 0、衬线、两端对齐；控制项范围统一校验，不让手写 JSON 绕过限制。
- 衬线 / 无衬线 / 楷体是语义角色，明确每个平台的可用字体与回退；系统字体存在不等于可嵌入、可分发。
- 原生预览保证基础排版、段落、卷章标题与封面一致；阅读器分页、字体替换不承诺逐像素相同。
- 自定义 CSS 仅追加到 EPUB / HTML 输出，不执行脚本、不加载外链。原生预览明确说明「附加 CSS 仅影响导出」，不引入 WebView 模拟任意 CSS。
- DOCX 只映射明确支持的排版属性；TXT / Markdown 不显示行高、字体等视觉选项已生效的假象。

### 7.4 嵌入字体

- 保留 Web 接受的 TTF / OTF / WOFF / WOFF2，初始单字体上限 20MiB；验证格式和文件读取，按书复制到资源目录，仅引用而非每次保存重写二进制。
- TTF / OTF 能否在原生预览加载，以真实运行验证为准；WOFF / WOFF2 可先保留为 EPUB 输出资源，不能因为 EPUB 支持就宣称 Flutter 原生预览支持。
- 明确嵌入后体积变化、用途和用户自备字体；不随项目捆绑来源不明的字体。
- 字体子集化不在本轮核心范围；后续增加时再评估体积收益、字形完整性与跨平台实现。

## 8. 导出契约与格式能力

### 8.1 共用输入

所有格式读取同一个 ExportSnapshot：当前书籍元数据、按序卷章 / 块、当前封面、排版、字体引用和固定的任务选项。先处理未保存内容，再在一致视图上创建输入。编辑后再导出的结果必须来自新内容；导出本身不改书稿。

二进制 ZIP 的时间戳、随机 ID 和编码器差异不要求逐字节一致；三端要求目录、文字、元数据和配置含义一致。需要可复现输出时固定时钟 / ID / ZIP 参数进行专用测试。

### 8.2 格式矩阵

| 格式 | 必须保留 | 本轮限制 / 明确提示 |
| --- | --- | --- |
| EPUB 3 | 封面、卷章、nav + NCX、可点击 toc.xhtml、完整元数据、基础排版、嵌入字体、附加 CSS | 不承诺原 EPUB CSS 和复杂图文保真 |
| EPUB 2 | 封面、卷章、NCX、toc.xhtml、基础元数据与排版、字体 | 不输出 nav.xhtml、epub:type、dcterms:modified；系列不按 EPUB 3 字段输出 |
| DOCX | 书名作者、Title / Heading 1/2、段落、可映射排版、合法 OOXML | Web 基线不含封面 / 插图，额外元数据不得假装全部支持 |
| 单文件 HTML | 书名作者、卷章标题、目录锚点、内联 CSS、转义后的正文 | 无脚本 / 外链资源；基线不嵌封面和插图 |
| TXT | 规范标题行、空行与正文；前言不强加标题 | 不带字体 / 封面 / CSS / 扩展元数据 |
| Markdown | 卷章映射标题级别、正文、必要转义 | 不承诺复杂块保真；不能因渲染符号改变原文语义 |

EPUB 具体要求：mimetype 为 ZIP 第一项且不压缩；container 指向合法 OPF；manifest / spine / nav / NCX / toc 的文件与锚点一致；封面后放目录页；单章正文超过约 40,000 非空白字符时按块拆 XHTML，仍只占一个逻辑目录项。拆分单位由 Bookloom 的统一字符规则定义并覆盖边界测试。

### 8.3 目标文件与完成条件

- 桌面使用原生保存目标；Android 使用 SAF / 分享服务，不能假定可以 rename content URI。
- 文件名处理 Windows 保留名称、非法字符、路径穿越、大小写冲突和批量同名；默认生成可预测的序号后缀，覆盖已有用户文件需要明确选择。
- 应用私有目录先生成临时结果，校验通过再提交到目标；外部提供者不支持原子替换时如实提示失败，不能宣传所有设备都原子保存。
- 用户取消保存 / 分享与真正的写入失败分开；分享面板打开不等于对方已收到文件。
- 失败保留当前书稿；可重试输出，不重复导入书籍；任务结束清理自己创建且不再使用的暂存文件。

## 9. 原生书架、任务与备份

### 9.1 书架与自动恢复

- 列表从数据库查询摘要，封面缩略图独立缓存；搜索与排序不加载全书正文。
- 不设任意书籍数量上限，受实际磁盘 / 内存预算约束；存储页显示应用书籍 / 原文 / 资源 / 缓存的实际大小。
- 全局最近书籍与每书 lastOpenedAt 分工明确；找不到最近项时回到书架，损坏项可以定位与恢复，不无限启动重试。
- 删除书籍先关闭编辑 / 暂停自动保存，再以可恢复的删除流程解除数据库引用和文件；重启后清理待删除残留，不能删掉其他书或用户原文件。

### 9.2 文件与数据库不能假装是同一个事务

导入使用任务专属 staging 目录，验证成功后移动到书籍私有目录，再提交数据库引用；提交失败清理该任务目录。对崩溃窗口保留最小操作标记并在启动时核对回收，不把完整书稿复制成历史版本。

删除、封面替换与恢复同样明确「先准备 → 校验 → 提交引用 / 替换 → 延后清理旧资源」的顺序。垃圾回收仅处理确认无引用且归属本应用的文件；磁盘空间不足、权限丢失和进程中断均有故障注入测试。

### 9.3 批量任务

- 现 Web 源码实际限制为 **40 本 / 单本 80MiB / 合计 200MiB**；README 的 20MB 建议是体验建议，不是 80MiB 输入上限。若旧资料写 20 本，以本文基线源码为准。
- 原生首轮以相同输入上限作为工程起点，串行处理并按设备内存实测再固化；上限不是「任意合法文件都能成功」的承诺。
- 一次队列固定输入、输出格式、ParseOptions、排版默认和转换方向，运行中不读取另一书籍正在修改的选项。
- 单本使用该书当前封面 / 字体；文件批量转换默认每本使用其输入封面或自动封面，不误用当前打开书的上传图 / 私有字体。
- TXT 批量默认自动编码，单个失败项可改编码后重试。结构化输入仍不暴露无效编码选项。
- 每项独立成功 / 失败；ZIP 只包含成功文件及本次结果清单，不伪造失败项文件。重试失败项不重做已成功项。
- 取消应能终止本任务正在运行的可中断计算，清理未提交结果，并标记剩余项；不能像 Web 那样只停止下一本却一直显示「已取消」。进入无法中断的外部提交阶段时说明正在完成收尾。
- 队列转换默认不污染书架；「加入书架」「导出已有书」是显式模式。当前轮不做常驻后台守护服务。

### 9.4 `.bookloom` 备份与恢复

这是 Bookloom 的原生增强，**当前 Web 没有整书项目 JSON 导入 / 导出功能可直接照搬**。

延续既有 ZIP 容器约定：`manifest.json`、`library.json`、assets、可选 sources。manifest 使用独立的备份格式版本、应用版本、UTC 导出时间、书数和是否含原文；不是直接复制一个仍有 WAL 的活动 SQLite 文件。

- 包含当前元数据、卷章、块、封面 / 字体资源、排版、解析参数、规则；不含撤销栈、日志、缩略图缓存、临时导出与账户数据。
- 默认包含原文，关闭时显示未来不能换编码 / 重新识别的影响。
- 备份使用独立的 `BackupLimits`，不套 EPUB / DOCX 的 32MiB 单条、128 / 256MiB 总解压上限。原文至少支持本轮允许导入的 80MiB 单文件；`library.json`、多书原文和资源按流逐项读取、校验并分批写入隔离恢复区，不把整包解压结果或全库 JSON 一次装入内存。增量解析与文件库能力在批次 A 验证，无法满足时先明确升级备份格式再实施，不用调大内存缓冲冒充流式处理。
- 恢复前依据声明大小给出空间预估与本次允许写入的预算，运行中按实际字节、条目、记录与字段大小持续限额；不信任 manifest 的数字。备份总大小受用户目标空间与取消能力约束，不以解析普通 EPUB 的内存预算限制合法多书备份。导出与恢复共享受支持的格式 / 预算约定，不能生成当前客户端自己无法恢复的包。
- 校验格式版本、资源哈希、引用与书籍 ID，再在隔离位置构建恢复结果；合并 / 覆盖不能误清空未选择的现有书。
- 同 ID 冲突提供跳过 / 覆盖 / 保留两份，默认保留两份；生成新 bookId 时同步重映射章节、块、source、asset 与 parent 引用。
- 正在编辑时先保存并暂停相关写入；恢复成功再刷新书架和会话。取消、坏包、新于当前支持的格式、缺资源、磁盘不足都不得破坏旧库。
- 有测试证明后才能声明「清空应用数据后完整恢复」；验收在可丢弃的测试环境进行，不能清空用户日常数据库。

### 9.5 从 Web 迁入

现有可靠通道是由用户在 Web 导出 TXT / EPUB / DOCX，再由 Bookloom 导入；各格式损失按第 8 节说明。规则 JSON 可单独迁移。

不直接读取浏览器 profile / IndexedDB，不猜测存在一个未定义的整书 JSON 备份。如果后续需要完整保留 Web 原文、字体、规则与当前编辑，应先在 Web 提供明确的用户导出格式和版本，再增加原生适配器；旧草稿 v1 / v2 / v3 和 sourceId 匹配用例可作转换参考，不能把浏览器数据库版本直接当 Bookloom schemaVersion。

### 10.2 平台验收点

- Linux：fcitx5 / ibus 中文组合、候选框位置、大段输入 / 选择 / 粘贴，窗口拖动、最小尺寸与不同 DPI。
- Windows：输入法、Unicode / 长路径、占用中的导出目标、大小写冲突、DPI 与窗口控制。
- Android：SAF 的 content URI、取消、授权失效、提供者读写失败、后台切换与进程重启、系统返回和软键盘；不以桌面路径测试代替 SAF。
- Android 先以可见任务完成长操作；后台限制下记录安全的未完成状态，下次启动可重试，不承诺进程被系统终止后继续转换。
- 冷启动恢复本地书架不依赖联网；简繁转换首次离线可用。外链更新日志 / 仓库 / 作者主页由用户主动打开，不加入后台遥测。
- 设备帮助保留 Kindle、Kobo、文石、汉王、掌阅等操作入口，但具体传输方式与兼容说明在实际发布前核验，不能把网页旧说明当当前兼容认证。

## 11. 安全、资源预算与依赖验证

### 11.1 一致的输入保护

检查覆盖单本、批量、重新解析、备份与字体 / 封面入口，不只保护主导入按钮：

- ZIP 条目路径禁止绝对路径、越界 `..`、符号链接逃逸；规范化后仍检查目录归属。
- 限制压缩包条目数、单条解压大小、解压总量、XML 深度 / 内容、图片像素和字体大小；压缩文件大小限制不能代替解压预算。按输入类型区分 `ImportLimits` 与 `BackupLimits`，路径、哈希与越界保护共用，但不能把所有 ZIP 都当作同一种文件。
- EPUB / DOCX 初始保护预算供批次 A 验证：单输入 80MiB、批量 40 个且总输入 200MiB、字体 20MiB；格式包最多 10,000 条目、单条解压 32MiB、总解压桌面 256MiB / Android 128MiB。图片解码像素预算在封面 Spike 中定值。TXT 原文与 `.bookloom` 恢复不受格式包单条上限约束；备份按第 9.4 节流式、实际写入预算与记录校验处理。预算需要集中配置并有越界测试，不散落在多个页面；未通过设备验证就调低并记录，不能为跑通样例直接关保护。
- XML 不解析外部实体、不读取外部文件或网络资源；HTML / XHTML 内容作结构化白名单处理，输出正文和元数据必须转义。
- CSS / HTML 不触发远程资源访问；拒绝外链 import / URL 或清晰移除并提示，不在原生侧执行书籍脚本。
- 字典 / 字体 / 第三方代码只采用可核验来源，随包保留适用的许可证与归属说明；本计划不授权下载不明资源或变更发布许可。

### 11.2 不把所有工作堆到主 isolate

编码检测、解析、全书体检 / 替换、转换、压缩与导出移至后台计算；可取消的正则和长任务使用可掌控生命周期的 isolate。只传可发送的任务数据，不传 Widget、ProviderContainer、SQLite 连接或跨 isolate 共享可变状态。

同时只运行一个统一的重任务；任务携带 jobId / revision。取消 / 超时以后迟到的消息丢弃，不能重新标成功。大书流式读取 / 分块处理，导出文件逐项落盘，避免同时持有输入字节、完整解压包、全书多份快照和完整输出 ZIP。

### 11.3 依赖 Spike 的出口

规划时 pubspec 尚未安装文件选择、ZIP / XML、图片编码、传统编码和 OpenCC 等业务依赖；实际选型与当前证据见第 14.3 节。原设计中的 `file_picker`、`archive`、`xml`、`image`、`share_plus` 及编码 / OpenCC 方案均是候选，**本文件不把候选包或旧版本写成已验证结论**。

批次 A 需要记录：实际选型与锁定版本、三个目标平台的构建能力、最小样例、离线资源体积、许可文件和阻塞项。GB18030 / Big5 完整性、WOFF 原生预览、Android SAF 不能只凭 API 名称判断。仅在证据证明 Dart 方案无法满足时再评估 FFI，不预先引入 Rust、服务端或外部常驻进程。

### 13.2 原生场景测试

1. 单本闭环：TXT → 分章 → 改标题 / 正文 → 分章 / 合并 → 撤销 / 重做 → 自动保存 → 进程重启 → EPUB 3。
2. 复杂校对：规则导入 → 命中预览 → 替换 → 体检 → 人工定位 / 重编号 → 撤销，内容与计数一致。
3. 成书：带封面 / 元数据的 EPUB、带 H1 / H2 的 DOCX → 编辑 → 各输出格式 → 结构 / 内容复核。
4. 多书：至少 20 本切换；更名、删除、封面和字体隔离；活动书保存失败不允许悄悄切走。
5. 批量：混合 10 个输入含 1 个损坏文件；其余成功、失败可重试、同名不覆盖、取消后状态不反跳。
6. 备份：独立测试库生成备份 → 清空该测试环境 → 恢复；比较书籍、层级、正文、元数据、封面 / 字体哈希、解析和排版选项。包含大于 32MiB 的原文、80MiB 输入边界、多书合计超过 128 / 256MiB 的合法包、未含原文的包，以及恶意虚报大小 / 越界写入，证明备份和普通格式包使用各自预算。
7. 故障：磁盘满、只读目录、SAF 失效、解析超时、提交阶段中断、坏 ZIP / XML、缺资源、更新后的旧任务消息。
8. UI：桌面与 960 附近断点、520 / 320 窄宽，1.5 / 2 倍文字；长标题、空列表、加载、失败、保存中、深浅色与三档磨砂；截图实际查看，疑点检查布局边界与运行日志。
9. 无网：首次启动后不用下载词典或字体即可导入 TXT、转换、编辑并导出；主动打开外链失败不影响本地工作。

### 13.3 性能目标与测量条件

沿用项目目标：普通笔记本 100 万字 TXT 解析并进入可编辑状态 ≤10s、1,000 章目录稳定滚动、章节切换目标 <100ms、已有书架冷启动目标 <2s。导出 EPUB 目标 ≤10s、峰值内存目标 <500MiB；这是工程目标，**不是已测结论**。

- 在批次 A 登记参考设备、数据集、release/profile 模式、冷 / 热缓存与测量范围；100 万字「可编辑」包含落盘和首章可操作，不只计分章函数。
- Android 单独记录机型与内存，低端设备可放宽耗时但必须可取消、不 OOM；具体平台预算在首轮基准后写回本节，不能直接移植 Web 的 0.3s / 5s 数值。
- 只加载目录摘要和当前章；输入与滚动期间不跑全书扫描、不每帧模糊大面积正文。
- 构建 / 测试使用宿主机工具，不为本项目构建 Docker 镜像；测试使用内存或独立临时 SQLite，不接用户日常库。
- CPU 密集任务默认最多约 75% 逻辑 CPU 且保留至少 2 线程，长期任务降低优先级，同一时间仅一轮重型构建 / 全量测试 / 性能测试。并发语义测试不能用限线程掩盖问题。
- 每阶段集中一轮必要完整验证，失败先汇总再修；仅在新修改 / 新失败 / 未解决疑点时复测。记录命令、时长、可取得的设备写入增量；不能取得就注明。
- 只改本计划时不启动应用或全套测试。将来若需要 Web 回归验证，使用归属可核验的独立可见浏览器，遵守全局 profile / PID 记录和退出清理规则。
